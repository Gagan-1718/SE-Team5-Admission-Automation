Team 5 · Sprint Two target

Admission Automation, finished

One website where a candidate goes from registration to an accepted seat, and one administrator verifies documents, runs the single allotment and publishes the results. Every step is gated by the step before it, shown on screen, and written to an audit log.

2roles: candidate and administrator
9stages from sign-up to seat decision
1allotment cycle, run once
20screens, one shared design
The story

Nine stages, one direction

Each stage opens only when the one before it is done. That is what makes the product logical: nobody can pick colleges before they are eligible, and nobody sees a result before the administrator publishes it.

  1. Candidate

    Register and sign in

    Name, email, mobile, date of birth, password. Lands on a personal dashboard.

    Opens: exam details
  2. Candidate

    Exam details

    Pick the seeded KCET or COMEDK record. Rank and category come from the record, never typed in freely.

    Opens: application. Frozen once submitted.
  3. Candidate

    Application

    Save a draft, come back, submit. A unique reference such as ADM-2026-000007 is issued.

    Opens: document upload
  4. Candidate Admin

    Documents

    Upload Marksheet, ID Proof, Category Certificate. The administrator approves or rejects with a reason; rejected files can be replaced.

    Opens: eligibility, when all three are approved
  5. System

    Eligibility

    Automatic. Pending until documents are approved, then Eligible or Not Eligible, with the rule that decided it.

    Opens: choice filling, Eligible only
  6. Candidate

    Choices

    Add college and branch pairs, reorder by preference, then lock. Locking is final.

    Opens: a place in the allotment run
  7. Admin

    Run allotment

    Once. Candidates in rank order, preferences in saved order, seats by category. Seat counts and results save together or not at all.

    Opens: publishing
  8. Admin

    Publish results

    Results stay hidden from candidates until this one click.

    Opens: result page for every candidate
  9. Candidate

    Seat decision

    Accept, or reject and withdraw. Exactly once. Not Allocated candidates see a clear explanation instead.

    Ends: the cycle
Consistency

Rules the product enforces

These close the gaps a reviewer would find by clicking around. Each is enforced on the server, not only hidden in the interface, and each has a test.

Exam details freeze at submissionA candidate cannot change rank or category after documents are approved or choices are locked.
Submit needs exam details firstEligibility needs rank and category, so the application refuses to submit without them.
Documents need a submitted applicationAlready true today. The dashboard now explains why the Documents step is locked.
Choices need EligibleNot Eligible and Pending candidates see why, with a link to fix it. Direct API calls get 403.
A locked list cannot changeAdd, remove and reorder are refused in the page and in the API once locked. Lock needs at least one choice.
Allotment runs once and refuses to waste the runNo locked lists means no run. A second run returns 409. A failed run leaves nothing behind.
Eligibility is checked again at run timeIf a cut-off or document changed after locking, the engine uses the current truth.
Results are invisible until publishedCandidates see "results not published yet". Administrators see the run summary.
One decision per allotted seatA database rule, not just a disabled button. Rejected seats are not released.
Every privileged action is auditedDocument review, catalogue and rule edits, candidate corrections, allotment run, publication. The log has no edit path.
Everything needs a loginIncluding the college catalogue. Only the landing, sign-in and register pages are public.
Forms and API calls carry a CSRF tokenOne central check instead of one per module.

Components to build once
  • App shell: role-aware sidebar, top bar, user menu, flash messages
  • Page header, card, stat tile, callout (info, wait, bad, ok)
  • Status pill, button set (primary, ghost, danger, good, disabled)
  • Step tracker, data table, form field with inline error
  • Empty state, confirmation dialog for irreversible actions
Rules for every page
  • Show names and references, never raw database ids
  • Every blocked step says why and links to the fix
  • Irreversible actions (submit, lock, run, publish, decide) ask first
  • Works at 400 px wide, keyboard operable, visible focus, labelled inputs
  • Print stylesheet for the allotment letter
